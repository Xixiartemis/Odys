# Odys Inner Agent Runtime (Phase E2)

Odys keeps the outer runtime authoritative: `Goal → Macro TaskGraph → Subgoal → InnerAgentExecutor → InnerAgentBackend → Agent SDK loop → Odys ToolRegistry → ToolResult → final claim → Outer Validator`. The inner backend may use multiple model turns and tool calls, but one outer Attempt remains one complete inner run.

`InnerAgentBackend` and its request/result models are provider-neutral. `ScriptedInnerAgentBackend` supports deterministic offline tests; `OpenAIAgentsBackend` is an optional OpenAI Agents SDK implementation. SDK tools are dynamically built only from the allow-listed, non-side-effect Odys capabilities. Tool failures are structured observations rather than immediate outer failures. The outer Validator still decides task completion.

The SDK backend requires `ODYS_AGENT_MODEL`; optional configuration includes `ODYS_AGENT_API_KEY`, `ODYS_AGENT_BASE_URL`, `ODYS_AGENT_API_MODE`, `ODYS_AGENT_PROVIDER_PROFILE`, and `ODYS_AGENT_SDK_TRACING` (default false). Provider profiles are explicit and conservative: `default` preserves the existing Responses/Chat Completions selection, while `mimo` selects Chat Completions and applies only the verified MiMo wire compatibility rules. An explicit `ODYS_AGENT_API_MODE` conflicting with a profile's preferred mode fails with `PROVIDER_PROFILE_API_MODE_CONFLICT`; explicit profile selection takes precedence over the default. MiMo never enables `previous_response_id`, `auto_previous_response_id`, or `conversation_id`. No secrets or hidden reasoning are persisted. Workspace, shell, browser, MCP, memory, multi-agent, and dynamic macro replan remain out of scope.
