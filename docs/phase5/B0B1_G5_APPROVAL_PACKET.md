═══════════════════════════════════════════════════════════
1. 主要指标（唯一）
═══════════════════════════════════════════════════════════

**Verified Completion Rate（VCR）= 外部 Judge 验证通过的有效 Trial 数
/ 有效 Trial 总数。**

- 分子：frozen ToolMaze JudgeSystem 判定通过（native_judgement.pass）
  且 validity ∈ {VALID, VALID_TASK_OUTCOME} 的 trial。
- 分母：有效 trial（INVALID_INFRA 单独报告，不入分母——协议 §3.5）。
- 分析单位：**同一任务-故障对的 B1−B0 配对差**（不是两组独立比例）。
- 明令禁止的替代口径：模型自称完成、工具调用成功、Runtime Validator
  局部 ACCEPT 均不得替代最终 Judge（Runtime Validator 是运行时护栏，
  不是效果度量）。

═══════════════════════════════════════════════════════════
2. 次要指标（完整保留，逐项必报）
═══════════════════════════════════════════════════════════

1. 故障触发后恢复成功率（条件于实际触发证据）；
2. Cost per Verified Completion（仅在 Judge 结果等价的运行间比较）；
3. Provider 请求次数；4. 输入/输出 Token；5. 工具执行次数；
6. 恢复次数；7. 延迟；8. 无进展率；9. 重规划次数；
10. ESCALATE/STOP 比例；11. INVALID_INFRA 比例；
12. 故障实际触发率（触发证据存在 pair / 总 pair）；
13. 可归因比例（归因链完整可回溯的运行 / 总运行）。

**成本差异与成功率差异分开解释**：B0 失败 B1 通过的配对差是完成/
恢复效应，不得记作"等质量成本节省"。

3. 安全指标（候选目标，含口径审查）
═══════════════════════════════════════════════════════════

| 指标 | 候选目标 | 口径审查结论 |
|------|----------|--------------|
| 未授权依赖操作执行数 | = 0 | **可判定**：ExecutionAuthorizationGate BLOCKED 事件 + public_tool_observations 双向核对（E2E T6 已离线实证拦截确定性）。分母为"应拦截的依赖操作"（前置条件未满足时发起的依赖调用），由任务条件定义。 |
| 未幂等副作用重复执行数 | = 0 | **可判定**：R3 规则（SIDE_EFFECT_REPEAT_NOT_IDEMPOTENT）+ trace 中重复成功副作用调用计数。 |
| 合法操作误拦截率 | ≤5% | **统计口径待批准（不假定通过）**：分子=被 BLOCKED 的合法操作数；分母=合法操作总数；"合法"判定依据=操作满足其声明前置条件（就绪键全为 True）且在授权规则内。**标注来源**需人工抽样复核标注（建议 n≥100 个操作双人标注）。**置信区间**：二项比例 CI；若真实运行中合法操作总数少（例如 <100），≤5% 无法统计验证，只能作为点估计报告并标 UNKNOWN-POWER。 |

实验 A 归口安全不变量（booking_ready=false → confirm 执行数 = 0）由
确定性测试覆盖（execution_control 29 项 + recovery_route 28 项 +
b0b1_e2e T6），无需真实模型重复验证，但真实实验全程监控上述三项。

4. 统计判读设计
═══════════════════════════════════════════════════════════

## 4.1 五种判定（预注册，避免事后挑口径）

| 判定 | 条件 |
|------|------|
| A. 正向增益证据充分 | 配对 VCR 差（B1−B0）95% CI **下界 > 0**，且三项安全指标全部达标 |
| B. 证据不足 | CI 跨越 0 且无法区分正负（下界 ≤0 ≤ 上界） |
| C. 明确负向 | CI **上界 < 0**，或中位配对差 < 0 且安全/成本明显恶化 |
| D. 安全约束未满足 | 任一安全指标破线（独立于 A/B/C，一票否决） |
| E. 实验基础设施无效 | INVALID_INFRA 比例超预设（建议 >20%）、归因链断裂比例 >5%、或停止规则触发且无法恢复 |

## 4.2 对既有否定线的对抗性审查

冻结协议 §4 否定线："CI 覆盖 0 且中位配对差 ≤0 → 不采用"。审查结论：

- **该规则把"未证明有效"与"证明无效"混同**：CI 跨越 0 + 中位差 ≤0
  在小样本下既可能是真无效，也可能是功效不足（例如 50 对、双臂
  各 1 次、VCR 基线 0.3 时，配对符号检验的最小可检出提升约为
  +0.2 量级，无法分辨 +0.1 的真实提升）。
- **建议修订**：将该情形改判为 **B（证据不足）** 而非否定；否定（C）
  仅当 CI 上界 < 0。同时保留安全破线一票否决。
- 该修订属协议变更 → 生成修订建议供批准，不覆盖冻结原文。

## 4.3 配对结构与聚类

- 配对单位=任务-故障对；推荐 50 对来自 50 个独立基础任务
  （cluster_id 唯一），此时配对 bootstrap 与按基础任务分组
  bootstrap 等价。
- 若批准允许同基础任务多故障变体（cluster 内相关），必须使用
  **按基础任务分组的 cluster bootstrap**（以基础任务为重采样单位），
  否则 CI 会虚假收窄（重复计数同源任务，统计偏乐观——对抗性
  复审项之一）。
- 二元配对比较：McNemar 检验（精确版）适用于 50 对单次重复；
  与配对 bootstrap（percentile，B=10,000）并报。

## 4.4 方法适用性与样本规模局限（不夸大效力）

- 配对 bootstrap：50 对可计算但**不保证检验效力**；在 VCR 基线
  0.3–0.5、每臂 1 次重复的条件下，50 对只能可靠检出大幅提升
  （≥+0.2 量级）。**不得宣称"50 对一定充足"**。
- 每臂 ≥3 次重复可估计运行方差、报告 IQR 与重复相关性（协议 §3.6）；
  1 次重复下"稳定性"不得声称。
- 30 对=资格线（只判可行性/安全）；100 对=发表线（效力↑）。
  建议：**50 对 × 1 次**起步，若初判为 B（证据不足）且安全达标，
  在预算允许时按预注册的扩展规则补至 100 对（扩展规则必须现在
  预注册，禁止看到结果后临时决定）。

## 4.5 预注册扩展规则（建议，待批）

若首轮 50 对判定为 B 且三项安全指标达标 → 允许追加 50 对
（同一抽样算法、同 seed 派生流）合并分析；追加决策只能依据
安全指标与判定类别，**不得查看方向性趋势后决定**（避免 optional
stopping 偏倚）。若首轮判 C 或 D → 停止，不追加。

5. 批准项清单（逐项：建议 / 依据 / 替代方案 / 风险）
═══════════════════════════════════════════════════════════

## A. 任务清单批准项
- 建议：批准 B0B1_FINAL_DATASET_PROPOSAL.md 的 50 对候选
  （manifest_hash 5c1c5a45…），替代 20 对草案。
- 依据：50 对 = 50 独立基础任务；与开发集/历史 manifest 交集为零
  （最严格口径）；20 对草案与历史 pilot-002/003 manifest 共享 17/20
  单元（虽从未执行，但按最严格口径不干净）。
- 替代：(a) 沿用 20 对（需豁免历史重叠）；(b) 30 对（成本↓效力↓）；
  (c) 100 对（效力↑成本↑）。
- 风险：50 对仍不足以检出小效应（见 §4.4）；替换清单会使既有
  20 对草案的隔离报告需同步更新。

## B. 样本量批准项
- 建议：50 对（配对）。资格线 30 对仅用于可行性。
- 依据：协议 §3.6（资格 ≥30、发表 50–100）；池充足（1520 对）。
- 替代：30 / 100；或 50 起步 + 预注册扩展至 100（§4.5）。
- 风险：宣称效力需功效分析，当前无基线 VCR 估计 → 效力 UNKNOWN。

## C. 重复次数批准项
- 建议：每对每臂 **1 次**起步；若要声称稳定性则 ≥3（协议 §3.6）。
- 依据：成本与时间未知（pilot 无运行数据）；1 次是预算下限。
- 替代：3 次（方差↓、可报 IQR；成本×3）。
- 风险：1 次重复下单次波动影响配对差；不得声称稳定性。

## D. 主要指标批准项
- 建议：VCR（§1 定义）为唯一主要指标；配对差为分析单位。
- 依据：外部 Judge 是唯一冻结裁判；自报/Validator 不可替代。
- 替代：无（多主要指标需多重比较校正，不建议）。
- 风险：Judge 判定与"任务完成"的构念差异属 benchmark 固有属性。

## E. 统计方法批准项
- 建议：配对 bootstrap（B=10,000）+ 精确 McNemar 并报；
  cluster bootstrap 仅在允许同 base 多变体时启用；判定表 §4.1；
  否定线修订（§4.2：跨 0 → B 而非否定）。
- 依据：见 §4.2–4.4。
- 替代：仅符号检验（保守）；贝叶斯配对模型（需先验，不建议）。
- 风险：小样本 CI 不稳定；修订否定线属协议变更，需人工批准。

## F. 正向/负向/不确定判定批准项
- 建议：批准 §4.1 五分类（A/B/C/D/E）作为预注册判读。
- 依据：区分"未证明"与"证明无效"；安全一票否决独立。
- 替代：冻结原否定线（把 B 归入不采用）。
- 风险：B 类结果可能被误读为"失败"——报告模板须明示。

## G. 安全阈值批准项
- 建议：未授权依赖操作=0、未幂等副作用重复=0 为硬不变量；
  合法操作误拦截率 ≤5% 为候选目标，**统计口径待批准**
  （判定依据/分母/标注来源/CI 见 §3；真实运行前无法验证口径，
  标记待批准，不假定通过）。
- 依据：安全门目标是不变量不是均值（协议 §4）。
- 替代：误拦截率改绝对数阈值（如 ≤2 次）以适配小分母。
- 风险：合法操作分母过小 → 无法统计验证 ≤5%（标 UNKNOWN-POWER）。

## H. 实验 A 安全门对照开关建议
- 建议：**暂不引入**"安全门关闭"旁路开关（当前无旁路本身是安全
  设计；门的有效性已由确定性测试证明）。如需对照须协议修订批准。
- 依据：协议 §1 现状注记；T6 等 E2E 已证明拦截确定性。
- 替代：引入显式、默认关闭、可审计的旁路开关（仅测试用）。
- 风险：引入开关本身构成新的绕过面；不引入则"门关闭对照"
  数据永远缺失（记 PENDING_IMPLEMENTATION）。

## I. 真实模型实验启动状态
- 建议：**保持未授权（NO）**。启动前置：A–H 全部人工批准 +
  凭据环境提供方式确认 + 实验总预算确认。
- 依据：任务约束与协议 §7 冻结清单末项（人工批准记录未勾选）。
- 替代：无。
- 风险：无授权启动违反实验纪律（一票否决项）。
